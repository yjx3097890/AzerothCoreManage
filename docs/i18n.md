# 多语言（i18n）

当前支持 **zh-CN**、**en-US**。默认：浏览器语言以 `zh` 开头用中文，否则英文；用户选择写入 `localStorage`（`acmanage.locale`）。

## 原则

| 内容 | 谁翻译 | 说明 |
|---|---|---|
| 面板文案（菜单、表单、按钮） | 前端 `web/src/i18n/locales/*.json` | 唯一来源 |
| API 错误 | `error.code` 稳定；前端用 `errors.<code>` 显示 | 后端也可按 `X-Locale` 填 `message`，给 curl 用 |
| SOAP / 游戏日志 / 角色名 / MOTD | **不翻译** | 来自 worldserver 的原文 |
| 任务编号 `P0-29` | 不翻译 | 与 `docs/tasks.md` 对齐 |

不要把中文写死在 React 组件里。新增页面时先加 key，再写组件。

## 前端

- 库：`i18next` + `react-i18next`
- Ant Design 的 `ConfigProvider.locale` 随语言切换（日期、分页、空状态）
- 顶栏和登录页都有语言切换
- 请求头：`X-Locale: zh-CN` 或 `en-US`

添加一句文案：

1. 在 `web/src/i18n/locales/zh-CN.json` 和 `en-US.json` **同一路径**加 key。
2. 组件里 `const { t } = useTranslation()`，使用 `t('nav.accounts')`。
3. 带参数：`t('errors.not_implemented', { task: 'P0-29' })`。

以后加第三种语言：复制一份 json，把 locale 加进 `web/src/i18n/index.ts` 的 `locales`，并在 `LanguageSwitch` 增加选项。

## 后端

- `api/internal/i18n` 根据 `X-Locale`（优先）或 `Accept-Language` 选择语言。
- 错误响应用稳定 `code`（如 `invalid_credentials`），`message` 为该语言的可读文本。
- 新错误：在 Go 的 `messages` 表和前端 `errors.*` **同时**加同一 code。

```json
{
  "ok": false,
  "error": { "code": "invalid_credentials", "message": "Invalid username or password" }
}
```

## 文档语言

仓库文档（`docs/`、`README.md`）目前以中文维护。面板 UI 的中英文与文档语言无关。
